# vibe-team 조직 설계 — 단계별 파트 × Claude·Codex 페어

- 날짜: 2026-10-07 · 결정자: 사용자 (요청 원문 기준), 설계 초안: Claude
- 출발점: claude-ecg-team (`5c9eb90` + 작업 트리 변경분)의 실행 도구와 조직 원칙

## 요청

1. 어떤 SW 를 만드느냐에 따라 단계별 파트(기획, 비즈니스분석, 통계, 시스템설계, 코어개발, 디자인, 테스트설계, 개발구현, 성능, 보안, 품질체크, CI, CD, Build, 배포, 아트, 사운드, 배경 등)를 구성한다.
2. 파트마다 역할에 맞는 스킬·역량을 가진 멤버를 둔다.
3. 파트마다 비판적 사고를 위한 Claude·Codex 페어를 둬서 객관적이고 가장 나은 선택에 도달한다.
4. 파트의 결과물은 다음 파트로 이어지고, 파트끼리 협업하며 수정 사항은 의견을 나눠 가장 합리적인 상태로 만든다.
5. 개발은 테스트 코드·개발·품질·성능·보안 체크를 기반으로 모든 테스트가 통과할 때까지 루프를 돈다.

## 실행 도구 변경 (claude-ecg-team 대비)

- `setup-team.sh`: 역할파일 `+` 겹침, `-n` 드라이런, 기본 팀 `discovery`, 진행자 이름 `진행-클로드`, team-send-verify Hook 을 저장소 간 중복 등록하지 않음, 스킬 이름 `vibe-send-verify`
- `bin/team-gate` 추가 + `tests/team-gate.sh`
- `team-send`·`team-status`·`team-checkpoint`·`lib/*` 는 문구·기본 팀만 변경

## 변경 이력

- 2026-10-07 (사용자 결정) — 페어 토론 방식: 모든 페어 작업은 Claude 가 먼저 의견을 제시하고 Codex 가 검토해 토론한다. 상반되면 최대 3라운드. 기존 "쟁점 독립 초안"과 "검증 파트 Codex 주도"를 대체한다.
  - 앵커링 보완: Codex 검토는 자기 대안 1개 이상(또는 대안 없음의 근거)을 포함한다.
  - 교차 검증 보완: 검증 파트에서 Claude(코드 작성자와 같은 모델)가 1차 판정을 내므로, Codex 는 판정문이 아니라 코드·측정을 직접 재확인한 근거로 서명한다.
